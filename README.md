# 手引き索引ツール

「保険診療の手引」の扉ページ索引と巻末索引を作るための、ブラウザだけで動くツールです。

- 原稿のPDFやExcelは、開いているパソコンのブラウザの中だけで処理します。どこにも送信しません。
- このリポジトリには、ツールのプログラムだけを置きます。**手引きのPDF・索引のExcelは置かないでください**（共有フォルダで保管）。

## 使い方（3つのボタン）

1. **設定**（改定のはじめに1回）
   前回の完成品のPDF（必須）と、引き継ぎファイル（あれば）を入れます。
   引き継ぎファイルが無いときは、前回の索引作業のExcel（語と読みの列があるもの）でも代わりになります。
   取り込んだ内容は、そのパソコンのブラウザに覚えておきます。
2. **確認用データを出す**
   新原稿のPDFを入れると、章ごとに打合せ用の作業Excel（上＝扉、下＝巻末）が出ます。
   施設基準の章のPDFも一緒に入れると、（施設基準）の行のページを仮に入れます。
   原稿が変わったときは、新しいPDFと、判定を書き込んだ前の作業Excelを一緒に入れると、判定を残したまま作り直します。
3. **業者に渡すデータを出す**
   - 扉ページ：判定の終わった章の作業Excelを入れると、その章の扉ページ（項目・ページ）が出ます。
   - 巻末索引：その時点の作業Excelを全部と、施設基準の章のPDFを入れます。全章そろって未決が0なら業者渡し用と「引き継ぎ_●●●●年版.xlsx」が、そろっていなければ試し出し（社内確認用）が出ます。

引き継ぎファイルは、完成品のPDFと一緒に共有フォルダに保管し、次の改定の「設定」で使います。

## GitHub Pages での公開

1. GitHub で新しいリポジトリを作る（例：`tebiki-sakuin`、Public）。
2. このフォルダの中身をすべてアップロードする（`index.html` がリポジトリのいちばん上に来るように）。
   ブラウザの「Add file → Upload files」は1回100ファイルまでなので、`lib/pdfjs/cmaps` フォルダを先に、残りをあとからの2回に分けて入れてください。GitHub Desktop を使う場合は1回で入ります。
3. リポジトリの Settings → Pages で、Source を「Deploy from a branch」、Branch を `main` / `(root)` にして Save。
4. 数分後に表示される `https://（アカウント名）.github.io/tebiki-sakuin/` を開くと使えます。

※ ツールは、ファイルをダブルクリックして開く（`file://`）と動きません。GitHub Pages か、手元で試すなら `python -m http.server` などで開いてください。
※ はじめて「確認用データを出す」を使うとき、読みの推定に使う辞書（約18MB）を読み込むので少し時間がかかります。2回目からはブラウザに残ります。

## 中身

- `index.html` `app.js` `app.css` … 画面
- `core/` … 処理の本体（PDFの読み取り、前回の索引との照合、Excelの書き出し・読み戻し、業者データ）
- `lib/` … 使っているライブラリ（pdf.js、ExcelJS、kuromoji と辞書）。ライセンスは `THIRD_PARTY_NOTICES.md`
